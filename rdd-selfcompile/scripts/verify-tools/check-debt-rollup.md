# check-debt-rollup.js —— 债账有没有真的进「下一步（汇总）」表

## 干什么

机检 `rdd架构\杂项记录\<YYYY-MM>.md` 的「## 下一步（汇总）」小节是否**真的吸收了本轮的债**。
输出五类问题码，任一出现即 WARN（不拦收工，但会被门禁喊出来）：

| 码 | 含义 |
|---|---|
| `NO_SECTION` | 找不到「## 下一步」小节 |
| `NO_DEBT_VOICE` | 该小节里没有任何一行提到「债 / 待修 / H 段」—— 债账没进表 |
| `COMPLETED_STILL_OPEN` | 某批次已在记录行里 ✅，但下一步表里仍以未划线 P0 挂着（表没刷新） |
| `H_SECTION_MISSING` | 没有 `### H ·` 小节（harness 自身维护项无处落） |
| `BATCH_NOT_LISTED` | （给 `--batch` 时）该批次没进下一步表 |

## 为什么需要（2026-10-20 #091 自审）

H1 的试金石是「三值化必须不经任何人提醒、自己浮进下一步表」。实测连续多轮为负：
主线报告越来越全（含「还不能用的」一节、复现命令、wire 取证工具），但**下一步表没刷新**——
完成的批次还挂在 P0，本轮新发现的技术债一条没进表。这件事靠「我记得」不成立，所以做成机检。

## 怎么调

```powershell
node check-debt-rollup.js                       # 当月
node check-debt-rollup.js --date 2026-10-20     # 指定日期所在月
node check-debt-rollup.js --batch G3e-2         # 额外核「本批进表了没有」
node check-debt-rollup.js --json                # 机读（harness-gate Q15 用这个）
node check-debt-rollup.js --selftest            # 证明它抓得住「表没刷新」（7 条）
```

退出码：`0` = 无 warn；`1` = 有 warn；`2` = 用法/环境错（文件不存在时按 WARN 降级，不冒充通过）。

## 它不做什么

- **不做语义判断**：只按表格结构（列位置）取「事/描述」格里的批次号，
  不去猜「这条算不算债」。想让它判更细，得先有更细的表结构。
- **不写文件**：只读。改表仍由人/AI 改（避免检查器变成第二个真源）。

## 什么时候不该用它

- 月底新开一份 `YYYY-MM.md` 时（新文件尚无「下一步」小节 → 会报 `NO_SECTION`，
  那是真的没有，不是误报）。
- 只想查一次「我这个批次的债进没进表」——直接看表更快；它存在的意义是**进 CI/门禁**。

## 依赖

- `harness-gate.js` postflight 的 **Q15「债账入表」**（WARN 级）。
- 无第三方依赖，Node 18+（用 `fs`/`path`/`os`）。
