## 一 · ★ 三方共识（本轮最有价值的产出）

Codex（C）、GLM（W）、Kimi（W）**三家独立**在同一问题上收敛：

| 问题 | Codex | GLM | Kimi | 共识 |
|---|---|---|---|---|
| 学习者能自己**调 AC / 身体动作**吗 | 不要 | **绝对不行** | **零权限** | ❌ 一律不行 |
| 学习者能自己**写经验**吗 | 可以（但需结构化参数） | 可以，**只 append** | 可以，**只写暂存区** | ✅ 可以，但 append-only |
| 不用向量怎么检索 | 改判定逻辑 | BM25 + 结构化 tag | **SQLite FTS5 + tag** | ✅ 词法/标签优先 |

### 1.1 为什么「调 AC」三家一致否掉（理由比我的更硬）

- **GLM**：「复盘是**事后的**，世界状态已过期，它调工具等于**用旧地图开车**。」
- **Kimi**：「双驾驶的真正风险不只是左右横跳，还有**目标冲突**（学习者想挖矿、主AI在逃命）、
  **状态竞争**（两个循环读到的世界状态不一致）。**执行器必须单写者**——主AI独占。」
- **Codex**：身体控制权要用宿主签发的租约仲裁，不能靠约定。

→ 我 v1 的 plan-only **方向被三家确认**，但**理由要升级**：不只是「怕撞红线」，
而是「事后快照驱动动作 = 用过期状态做决策 + 多写者竞争」。

### 1.2 「写经验」的正确形态（三家一致，我没做到）

v1 我做的是**只出草稿、由主AI转写**。三家都说这多了一道：
- **GLM**：「简化方案：learner 直接写，**标 pending**，主AI验证后升格；不需要『采纳后再由主AI转写』的多余环节」
- **Kimi**：「只能写暂存区（staging），不进正式库」
- 三家共同强调两条硬规则：
  1. **append-only**：不能改、不能删、不能合并已有条目（防改写自己的学习记录）
  2. **成功率只能由外部真值更新，绝不能 learner 自评** —— 否则它会写「这策略很棒」然后自我强化

### 1.3 不用向量的替代（比我的方案更具体）

我 v1 用的是「LLM 改写 query + 现有词法检索」。两家都指向**结构化字段优先**：

- **Kimi**：「写入经验时让 LLM 顺手产出：摘要 + 关键词 tag + **结构化字段（涉及物品、生物群系、技能名）**；
  检索 = 结构化字段过滤（精确）+ FTS5/BM25 排序（模糊）。**Voyager 的技能库检索其实大部分场景结构化匹配就够了，向量是锦上添花。**」
- **GLM**：「Minecraft 是**封闭域，词 gap 小**（『钻石镐』就是『钻石镐』），embedding 解决的语义漂移问题在这里不严重。」
  并警告：「**别硬套 Voyager 的固定 top-5**。候选质量差时**返 0 条比硬凑 5 条好**，
  『无相关记忆』本身是有效信号。」

→ 修正我 28 号文档里「抄 Voyager 向量 top-5」的表述：**先做结构化 tag + 词法，向量是后手且可选**。

## 二 · ★ 我完全没想到的 8 个风险（两家/一家提出）

1. **建议不能流式注入执行中上下文**（GLM，最关键）
   > 「learner 的建议只能**队列化、在主AI的规划阶段读取**，**不能流式注入执行中的上下文**——
   > 否则建议文本在动作中途出现，主AI当场改主意，**这是文本形式的第二驾驶，横跳换个马甲而已**。」

   → **v1 有这个漏洞**：`learner_review` 的输出是通过 MCP 回给 AI 的，AI 可能正在执行中。
   正确形态应是「写进队列，下一轮规划时读」。

2. **记忆污染放大 / 自我强化回路**（GLM+Kimi 同时提）
   > 「错误经验被检索 → 被执行 → 复盘又『验证』了它 → 置信度越滚越高。」

   → 与 1.2 的「成功率只能外部更新」同源，但**没被我写进任何文档**。

3. **建议会过期**（Kimi）
   > 「学习者建议基于快照 A，主AI执行时世界已到状态 B。建议对象**带前置条件和 TTL**，执行前校验。」

   → 我的 `Verdict` **没有 precondition / TTL 字段**。这是数据模型的缺口。

4. **Prompt 注入**（Kimi 独有）
   > 「游戏内聊天、告示牌、书本文字进入记忆后被检索进 system prompt。
   > 外部文本永远**标记为不可信数据**，检索结果与指令隔离。」

   → **完全没想到**。备忘录里如果有告示牌/聊��内容，就是注入面。

5. **边界要可审计，不能信 prompt**（GLM）
   > 「所有工具调用记 **caller ID**，learner 出现在 caller 里就报警。**别信任 prompt 边界，要信任日志**。」

   → 这和 Codex 的「`InvocationContext` 由宿主签发，不能只信调用者填一个 `"learner"` 字符串」**是同一条**，
   但 GLM 说得更狠：**要靠日志审计，不是靠约定**。

6. **死亡循环 / 失败模式黑名单**（Kimi）
   > 「同一死法反复发生但**没有失败模式黑名单**。失败经验要能被检索为『别这么做』，**不只是成功经验库**。」

   → 我们的 `ExperienceType` 有 `FAILURE`，但**没有「禁止重犯」语义**。

7. **条目冲突与膨胀**（GLM）
   > 「记忆里『A 说往下挖』和『B 说永远别往下挖』同时被检索，主AI直接懵。
   > 一课一条、字数上限、按主题去重、**冲突时按成功率+新近度裁决**。」

8. **没有评测回路**（GLM+Kimi 都列为最优先）
   > 「同一任务，learning on/off 各跑 N 局比成功率。否则你们分不清『在学习』和『在产生噪声』。」

   → **我完全没做**，且它是判断这套东西有没有用的**唯一客观依据**。
