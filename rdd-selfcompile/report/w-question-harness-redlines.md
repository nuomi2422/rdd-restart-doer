## 一、harness 是什么（九步流 + 门禁）

`rdd-selfcompile/scripts/flow-gate.js` + `loop-gate.js` + `stager` 状态机

```
①计划统筹 → ②编码实现 → ③游戏验证 → ④记录收口 →（轮回 ①，轮次+1）
```

| 层 | 作用 | 机制 |
|---|---|---|
| **stager** | 阶段状态机，改 `stages.json` 即改流程 | 每阶段 `read[]`（必读 md 路径）+ `gate`（不达标不许 next） |
| **flow-gate** | 查盘上实物 | 部署 jar 的 sha == 构建产物 / 回滚点齐 / mutation 有 build-deploy-verify 的 phase-*.json |
| **loop-gate** | 20 项九步流硬门 | mtime 新 + 内容含本轮签名 两条腿（防匹配到旧文件） |
| **run-mutation.ps1** | 唯一改码入口 | 手写 gradle / 手动拷 jar 已被 permission deny |

**我们给每项门禁打了性质标签**（🔒查实物 / 📝查痕迹 / 👤人工），实测占比 flow-gate 4:4、loop-gate 5:15。
**标签只在 `--human` 时显示** —— 因为 AI 读得到门禁输出，标签等于给它一张「哪些检查可以糊弄」的地图。

**我们知道的自身缺陷**（外部评审指出，我们认）：
- 门禁里 75% 是「查痕迹」，能被敷衍
- 我们把「系统不变量」和「任务门禁」混在同一层 → 无关红项劫持当前任务（已加豁免记账制缓解）
- 空壳文档判据已从「长度」换成「本轮 commit 签名」（长度是 Goodhart 代理指标）

## 二、已验证的任务链红线（RL-1..RL-17）

### 主链路（必须逐字保留的规划-判定-执行大链）
```
用户目标 → 规划器（LLM 拆二级子任务）→ 条件判定（Detector 用世界证据验收）
        → 执行器（Numen 操作身体）→ 回填资产历史 → 下一步
```

**核心设计**：完成事实独立于当前库存；跳过不伪造 COMPLETED。

### 红线 RL-1..RL-17（分两批）

**第一批 RL-1..RL-9**（设计阶段定）：
覆盖规划器输出合法性、条件判定的证据来源、单驾驶员（观察/规划/修复编排不并发夺身体）、
执行异常转任务失败（`AbstractCompanionTask`）、不让学习者提交身体动作（RL-9）等。

**第二批 RL-10..RL-17**（2026-09-30 实机后补登）：

| 编号 | 内容 |
|---|---|
| RL-14 | 台账判据必须带**批次身份 + 数量**（不能只问"现在有没有"） |
| RL-15 | 状态必须**活得过重启**（进程内静态 Map 重启即丢） |
| RL-16 | 纯逻辑单测全绿 ≠ 判据接对了宿主 |
| RL-17 | 修复反射优先级时，先问会不会压掉号更大的救命反射 |

**RL-14/15 来自一次真实事故**：
```
死亡掉落回收用 AssetHistory 长期累积表 + confirmRecovered(-1)
→ 33 格掉落捡回 1 格就判整条支线成功
→ 连死两次时，上一批的掉落替这一批结账
修法：Death 记录带 lostItems(物品→数量)，判据只认当前支线对应的 deathSeq，
     逐项核对 min(当前持有, 当次丢失数)
```

## 三、这一轮实机验证了什么（真跑出来的，不是设计稿）

**六项缺陷修复，F1/F2/F4a/F6 实机已验**：
```
F1 PAUSE 开关        flag 删→subtask_paused+1；flag 建→pause_skipped_disabled+1 且不增
F2 台账跨重启       重启后 deathSeq:3 接着磁盘号，seq 1/2 保留
F4a 自我保护前置    repeat_death_nearby{previousDeathSeq:4, secondsSincePrevious:142} + 新文案送达
F6 逐项回收判据     trackedItemKinds:18 → seq3 RECOVERED，结在正确 seq
全仓回归 1657 项 / 0 失败
```

**顺手抓到两个真缺陷（单测测不到）**：
1. `repeatDeathWithin` **自匹配** —— 只杀一次就误报"同点连死"（`secondsSincePrevious:0`）
2. 死亡瞬间**只读 body 返回空** → `trackedItemKinds:0` → 逐项核对完全失效

**根因同类**：判据本身正确，**喂给它的数据或时序错了**。纯 JVM 造不出「台账里已含本次死亡」「实体刚死、物品栏已被原版处理」这两个时序。

**F3/F5 未验**（会话头隔离只有一个同伴、acquire 无 mode 入口）—— 如实标未验，不写进任何文档。
