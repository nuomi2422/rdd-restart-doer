### ② 新工具 `use_portal`（修回不了主世界）⚠️ 编译+部署完，**行为未验**

**你报的 bug**（实机日志坐实）：
```
23:12:31  Iris: Reloading pipeline: overworld => the_nether     ← 它进了下界
23:16:05  dispatch tool=goto  args={"block":"minecraft:nether_portal"}   ← 又在找门
23:16:06  goto FIND nether_portal → 6 hit(s), nearest 59,56,-43          ← 那是上界坐标！
23:14:53  MoveToCompanionTask FAILED(NO_PATH) blocked: got within 185.5 blocks
```

**真因**（不是"不识别门"）：
1. `goto` 的契约是**「走到旁边」**——它停在门旁一格就宣告成功，**从不 USE 那块门**
2. 全仓**没有任何跨维度代码**（搜 `NetherPortalBlock.process` / `changeDimension` 全无命中）
3. 于是：走到门旁 → 还在下界 → 再 `goto` → 同一个门 → **无限循环**
4. 附注：它拿的是**上界坐标**（下界 x/z 是上界的 1/8），下界当然找不到

**修法**：新增独立的 `use_portal` 工具 = `找到 → 走过去 → 静置 → USE`。
**为什么不改 `goto`**：它的"停在旁边"被 `place_block`/`break_block`/`mine` 一整串任务依赖，
塞"到了就 USE"会让"去工作台"和"进门"产生歧义。

**重启后怎么验**（一条命令）：
```
给它一个下界任务 → 等它进下界 → 观察它是否调 use_portal 而不是反复 goto
```
日志标记：
```
[numen-task] use_portal start kind=nether in minecraft:the_nether target=minecraft:nether_portal
[numen-task] use_portal found portal at x,y,z
[numen-task] use_portal USED portal at x,y,z (from minecraft:the_nether) result=...
```

**注意**：`use_portal` **不搭门**。下界要有门才能回家；没门它会明说"范围内没有门"，
这时得先自己搭（10 黑曜石 + 打火石）。
