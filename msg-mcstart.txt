## mc-start.js 用法（只有一个位置参数）
    node mc-start.js                    # 默认 gpt / 10 分钟
    node mc-start.js gpt 60             # 实例 + 运行时长
    node mc-start.js gpt 10 --status    # 查状态，秒回
    node mc-start.js gpt 10 --stop      # 关
    node mc-start.js gpt 10 --wait 0    # 只脱离启动，不轮询

## 三个最贵的坑怎么封
| 坑 | 症状（会误导排查方向） | 脚本做法 |
|---|---|---|
| **shell 阻塞** | 卡 10 分钟，而 MC 其实早起来了 | spawn(detached)+unref，父进程秒退，句柄不继承 |
| **参数绑定失败** | java 进程一直是 0，**看起来像 OOM / mod 崩** | 用哈希表 splat（按名字传参），不是数组 splat |
| **内存不足伪装成 mod 崩** | 加载中途消失、零异常 | 起之前查空闲内存，<1200MB 直接拒起并说清原因 |

判据只看「实际发生」：java 进程 / latest.log 增长 / session.lock 更新 / MCP 8765 可连，
连续两次齐了才算起好 —— **不看脚本退出码**。

## 实测
- `--status`：8.8 秒返回，正确识别「已在跑」
- 空闲内存 1MB 时：**拒绝启动 + 说清原因**，7 秒返回（没有卡）
- 「已在跑」分支：秒退，不重复启动
